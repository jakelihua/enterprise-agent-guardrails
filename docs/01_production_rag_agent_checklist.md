# 企业级 AI Agent 与 RAG 生产上线 20 项通用防崩盘 Checklist（2026 开源纯净版）

> **作者**：极客李华（微信公众号同名）  
> **版本声明**：本清单 100% 基于公开学术论文（Stanford / Anthropic / Princeton / Berkeley LMSYS）与通用开源分布式系统工程实践（MIT / Apache-2.0 生态）提炼而成，适用于任何基于 LLM 构建对话助手、知识库检索（RAG）与多智能体（Multi-Agent）工作流的研发与产品团队。

---

## 模块一：长上下文预算与多路路由防爆（Context & Routing）

### ☐ 01. System Prompt 静态元数据体积红线（`<= 1,500 Tokens`）
- **常见翻车现象**：将几十个工具定义（Tool Schemas）或上百个知识库的详细描述全量硬塞进 System Prompt，导致用户还没说话，每次请求先白烧上万 Token，首字延迟（TTFT）从 `0.5s` 劣化至 `4s+`。
- **自检达标线**：静态 System Prompt 严格控制在 `1,500 Tokens` 以内；超过 10 个以上的数据源或工具时，必须采用**「两级分层路由（先选大类领域 -> 再动态挂载子集 Tool/KB）」**。
- **公开理论与开源参考**：Stanford *Lost in the Middle: How Language Models Use Long Contexts* (TACL 2024)。

### ☐ 02. Prefix KV Cache 命中率保护（静态前缀零抖动）
- **常见翻车现象**：在 System Prompt 最开头拼接了精确到秒的动态时间戳（`Current Time: 2026-11-20 11:42:05`）或随机 `request_id`，导致大模型推理引擎的 Prefix Caching 100% 失效，算力成本暴增 3~5 倍。
- **自检达标线**：所有高频变动的动态变量（当前时间、用户本轮检索片段、会话状态）一律后置到 Prompt 尾部或 User Message 中；固定不变的指令、Few-shot 示例严格锁死在最前端。
- **公开理论与开源参考**：vLLM Automatic Prefix Caching (APC) / Anthropic Prompt Caching 官方架构指南。

### ☐ 03. 相似意图与近似工具的“消歧兜底”机制
- **常见翻车现象**：当多个知识库或工具的描述语义高度重叠（余弦相似度 `> 0.85`）时，路由模型在 Top-1 选择上出现随机摇摆。
- **自检达标线**：当 Top-1 与 Top-2 路由得分差值 `< 0.08` 时，禁止盲目单选，必须触发**「双路并行检索合并」**或**「向用户发起一句话反问澄清」**。

### ☐ 04. 历史会话滑动窗口与摘要压缩（防止多轮 OOM）
- **常见翻车现象**：长对话不设截断，第 20 轮对话时把前面所有工具返回的原始 JSON 全量带入，触发 `Context Length Exceeded` 或注意力涣散。
- **自检达标线**：工具返回的巨型原始 Payload 只在当轮消费，进入历史记忆前必须裁剪为 `< 300 Tokens` 的结构化摘要；保留最近 `N=6` 轮原文 + 早期对话滚动摘要。

### ☐ 05. 模型网关降级与跨厂商 Fallback 路由
- **常见翻车现象**：单点绑定某一家商用 API，遇到上游限流（HTTP `429`）或机房抖动（HTTP `502/503`）时整个业务直接不可用。
- **自检达标线**：网关层配置自动熔断与备用模型热切（设置 `max_retries=2`，退避时间 `0.5s -> 1.5s`，超时立即切换至同量级备用模型端点）。
- **开源参考组件**：LiteLLM / Envoy AI Gateway。

## 模块二：多模态文档解析与 RAG 检索降噪（Ingestion & Retrieval）

### ☐ 06. 多模态文档“5-Line OCR”装饰碎图清洗规则
- **常见翻车现象**：解析 PDF/Word 报告时，版面分析工具将页眉 Logo、页脚水印、分割线、小图标全部切为独立图片送入视觉大模型（VLM）生成描述，导致 80% 算力浪费在垃圾碎图上，且污染向量库。
- **自检达标线**：图片进入 VLM 前必须经过轻量级几何与 OCR 预筛——**凡是尺寸 `< 120×120px`、长宽比极端（`> 8:1` 或 `< 1:8`）、且内部可读文本少于 5 行的图片**，默认标记为装饰性元素并跳过 VLM 重度推理（开启 Fail-Open 容错保留原图索引）。
- **开源参考组件**：OpenDataLab MinerU / PaddleOCR / LayoutLMv3。

### ☐ 07. 跨页长表格“表头上下文锚定（Header Injection）”
- **常见翻车现象**：长达数页的财务或参数表格被按固定字数（如 500 字）强行切断，第 2 页以后的切片丢失了第一页的列头定义（`Column Headers`），导致检索出的数字张冠李戴。
- **自检达标线**：表格切分必须以“完整逻辑行”为单位；拆分为多个 Chunk 时，**每个子 Chunk 顶部必须强制自动拼接原始表头行与所属章节标题路径**。

### ☐ 08. 混合检索（BM25 稀疏 + Dense 稠密）与 RRF 重排
- **常见翻车现象**：纯向量检索（Dense Embedding）对精确的产品型号（如 `RTX-5090-D`）、错误码（`ERR_CONNECTION_RESET`）、专有名词极不敏感，经常召回语义相近但型号完全错误的段落。
- **自检达标线**：生产环境严禁只用纯向量检索；必须启用 **全文关键词检索（BM25/全身索引） + 向量语义检索**，并通过倒数秩融合（RRF）或 Cross-Encoder Reranker（如 `bge-reranker-v2-m3`）取 Top-K。

### ☐ 09. 父子文档块映射（Small-to-Big Retrieval）
- **常见翻车现象**：Chunk 切太小导致上下文残缺不全；Chunk 切太大导致 Embedding 语义被稀释、检索不准。
- **自检达标线**：检索索引使用细粒度子块（`200~300 Tokens`）保证高命中率；命中后向大模型喂入其对应的父级完整段落（`800~1,200 Tokens`），兼顾检索精度与生成完整性。
- **开源参考组件**：LlamaIndex `ParentDocumentRetriever`。

### ☐ 10. 空召回与低置信度“诚实拒答”阈值
- **常见翻车现象**：知识库里根本没有相关资料，但因为固定取 `Top-5`，系统把相似度只有 `0.32` 的无关段落硬塞给大模型，逼出满嘴胡编的幻觉。
- **自检达标线**：在 Rerank 阶段设立硬性相关性门槛（Score Threshold）；若所有召回块得分均低于阈值，直接短路返回确定性的“当前知识库未收录该信息”，严禁让大模型强行脑补。

## 模块三：高并发流式网关与状态机防死锁（Concurrency & Runtime）

### ☐ 11. 异步连接池有界信号量（Bounded Semaphore）与背压控制
- **常见翻车现象**：Python `asyncio` 或 Go 服务在高并发下无限制创建协程调用外部工具，瞬间打满下游数据库连接池或触发文件描述符耗尽（`Too many open files`）。
- **自检达标线**：所有外部 IO 调用必须包裹在有界并发池（如 `asyncio.Semaphore(MAX_CONCURRENCY)`）与显式队列超时（`queue_timeout`）中，满载时快速失败（Fast-Fail）而非无限堆积内存。

### ☐ 12. 多 Agent / 群聊机器人防无限互调死循环（Loop Storm Guard）
- **常见翻车现象**：两个或多个自动化 Bot 在同一群聊或事件总线中互相触发，陷入“礼貌道谢”或“报错重试”的死循环，一夜之间刷爆几千万 Token。
- **自检达标线**：
  1. 消息头强制携带 `hop_count (TTL)`，最大跳转次数 `<= 3`；
  2. 针对同一会话窗口配置滑动窗口频控（如 60 秒内同一 Bot 最多连续响应 3 次即触发冷却熔断）。
- **公开理论参考**：ACL 2024 *ChatDev* / NeurIPS 2023 *CAMEL* 终止条件设计。

### ☐ 13. SSE 流式响应首包心跳与客户端断连级联取消
- **常见翻车现象**：复杂 Agent 思考耗时超过 15 秒，中间网关（Nginx / ALB）因长时间无字节传输直接掐断连接（`504 Gateway Timeout`）；或者前端用户早就关掉网页了，后端还在傻乎乎继续调大模型烧钱。
- **自检达标线**：
  1. SSE 建立连接后每 `3~5 秒` 发送一次空注释心跳帧（`: keep-alive\n\n`）或思考进度事件；
  2. 监听客户端 `request.is_disconnected()`，一旦前端断开，立即通过 `CancelToken / task.cancel()` 终止后续大模型与工具调用链。

### ☐ 14. 外部工具调用的幂等键（Idempotency Key）设计
- **常见翻车现象**：Agent 调用“发送邮件”、“创建工单”、“扣减额度”等写操作工具时，因网络抖动触发超时重试，导致同一封邮件连发 3 次或重复扣费。
- **自检达标线**：所有具备副作用（Side-Effect）的写操作 Tool，必须由框架层自动生成基于 `(session_id, turn_id, tool_name, args_hash)` 的幂等键，确保重试不重复执行。

### ☐ 15. 附件解析与代码执行的沙箱资源隔离（cgroups / Docker）
- **常见翻车现象**：恶意或畸形的超大压缩包（Zip Bomb）、百万行 Excel 或死循环脚本直接在主服务进程内解析，导致整个 Web 节点 CPU 100% 或 OOM 崩溃。
- **自检达标线**：重度文件解析与代码解释器必须在独立的受限子进程或无网容器（`--network none --memory 512m --cpus 1.0 --pids-limit 64`）中运行，超时立即 `SIGKILL` 回收。

## 模块四：输出确定性护栏与离线回归门禁（Guardrails & Evaluation）

### ☐ 16. 算术与精确逻辑的“零 LLM 计算卸载（Code Offloading）”
- **常见翻车现象**：让语言模型直接心算多列财务报表求和、同比增速、 compound interest（复利）或日期差，出现“过程写得头头是道、最后一位数算错”的致命幻觉。
- **自检达标线**：严禁让 LLM 直接输出复杂数学运算结果；必须强制模型输出结构化计算公式或 Python/SQL 表达式，交由后端确定性 AST 求值器或 `decimal.Decimal` 引擎计算后再填入回复。
- **公开理论参考**：ICML *PAL: Program-aided Language Models*。

### ☐ 17. 结构化输出 Schema 强校验与自愈重试（Structured Outputs）
- **常见翻车现象**：下游业务代码依赖模型返回的 JSON，结果模型偶尔多加了一句 Markdown 解释或漏掉一个必填字段，导致 `json.loads()` 抛异常崩溃。
- **自检达标线**：全面启用原生 `Structured Outputs / response_format` 或 Pydantic 强类型校验；解析失败时将 Pydantic 报错信息作为 Feedback 自动回传模型进行 1 次局部修正（Self-Correction）。

### ☐ 18. 引用溯源防伪造校验（Citation Grounding Verification）
- **常见翻车现象**：Prompt 要求模型“附上原文链接或文档编号”，模型为了讨好指令，自己编造了一个看似逼真但根本不存在的 URL 或条款号。
- **自检达标线**：不要让模型从零拼写长 URL；检索阶段将每个参考片段编号为 `[Ref_1]`, `[Ref_2]`，只允许模型输出引用编号，由后端代码在渲染时将其确定性地替换为真实链接，并校验所引编号是否确实存在于当轮检索上下文中。

### ☐ 19. 拒绝“按天盲改 Prompt”：建立百题黄金回归集（Golden Dataset）
- **常见翻车现象**：老板或客户每报一个 Badcase，研发就往 System Prompt 里打一行补丁；改了第 10 个 Bug，前面调好的 50 个场景悄无声息全崩了（跷跷板效应）。
- **自检达标线**：上线前必须固化至少 `100~300 条` 覆盖核心主路径、边界异常与对抗诱导的黄金测试集；任何 Prompt、切分策略或模型版本的变更，必须跑通自动化评测流水线且核心指标无显著倒退方可合入主干。
- **开源参考组件**：Promptfoo / Ragas / DeepEval。

### ☐ 20. 摒弃“单次平均分迷信”：引入置信区间与分项 Rubric 门禁
- **常见翻车现象**：用 LLM-as-a-Judge 笼统打一个 `1~10` 分，两次实验分别是 `8.2` 和 `8.4` 就宣布优化成功，实际上只是采样随机噪声。
- **自检达标线**：将主观总分拆解为原子化的二元判定项（`Yes/No Rubric`，如：“是否包含未提及的免责条件？”、“数字是否与表格第3行完全一致？”），并通过多次采样或 Bootstrap 计算置信区间，只有统计显著提升才予以放行。
